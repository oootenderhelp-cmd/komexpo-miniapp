# Развёртывание платформы

Что нужно, чтобы поднять рабочую версию. Порядок важен: без базы приложение
запустится, но заявки сохранять не сможет.

## Что должно быть у вас на руках

| Что                   | Где берётся                         | Зачем                                        |
| --------------------- | ----------------------------------- | -------------------------------------------- |
| Хостинг с Node.js 20+ | Beget, Timeweb, Reg.ru, любой VPS   | Где живёт приложение                         |
| Домен                 | Там же или у регистратора           | Адрес формы и вход клиник                    |
| SSL-сертификат        | Обычно бесплатный в панели хостинга | Без HTTPS форму браузер пометит небезопасной |
| MySQL 8               | В панели хостинга                   | Где лежат заявки                             |
| Почта для писем       | SMTP хостинга                       | Уведомления                                  |

Регистрацию хостинга, домена и рекламных кабинетов выполняет владелец бизнеса
лично: это договоры и оплата от вашего имени.

## Переменные окружения

Создайте `.env` рядом с проектом:

```
DATABASE_URL=mysql://пользователь:пароль@localhost:3306/имя_базы?charset=utf8mb4
JWT_SECRET=<случайная строка от 64 символов>
OWNER_OPEN_ID=<логин владельца>
VITE_APP_TITLE=Заявки в стоматологию

# Счётчики — можно заполнить позже
VITE_YANDEX_METRIKA_ID=
VITE_VK_PIXEL_ID=
```

`charset=utf8mb4` обязателен, иначе кириллица в заявках превратится в вопросы.

## Запуск

```bash
pnpm install
pnpm db:push      # создаст таблицы
pnpm build
pnpm start        # порт из PORT, по умолчанию 3000
```

Приложение слушает HTTP; наружу его выставляет nginx или панель хостинга с
проксированием на этот порт и включённым SSL.

Держать процесс живым — через systemd, pm2 или менеджер процессов хостинга.
Без этого приложение умрёт при первой перезагрузке сервера.

## После запуска: первые шаги

1. Зайти под владельцем, открыть `/dental/leads`.
2. Вкладка **Клиники** — добавить хотя бы одну клинику-партнёра. Пока клиник
   нет, заявки будут копиться нераспределёнными.
3. Вкладка **Источники** — выпустить ключ для каждого сайта и формы, откуда
   ждём заявки.
4. Проверить форму `/dental`: оставить тестовую заявку и убедиться, что она
   появилась в очереди и ушла клинике.
5. Заполнить счётчики Метрики и пикселя VK, поставить цель на заявку.
6. Запустить кампании по семантике из `docs/dental-traffic.md`.

## Проверка перед сдачей

- Форма открывается по HTTPS, без предупреждений браузера.
- Тестовая заявка сохранилась, попала в очередь и ушла клинике.
- Excel выгружается и открывается, кириллица не побилась.
- Критичная заявка создаёт уведомление администратору.
- Отзыв согласия на `/dental/opt-out` работает по номеру заявки.
- Внешний вход отвечает 401 без ключа и принимает заявку с ключом.

## Что нельзя выкладывать в репозиторий

Пароли базы, `JWT_SECRET`, ключи источников и токены рекламных кабинетов.
Всё это живёт в `.env` на сервере; в репозитории лежит только `.env.example`
без значений.
